Inicialización de datos
PRELOAD + seed automático Docker
58 servicios hardcoded como constante PRELOAD (Abril 2026). En Docker, start.sh copia el JSON seed al volumen si no existe sla_bd.json.
Sincronización multi-ventana
Polling cada 15 segundos
En modo servidor: setInterval(15000) detecta cambios en savedAt. Si cambia, merge en estado React + toast "🔄 Sincronizado".

Flujo 3 — Lógica de negocio SLA
Cálculo de estado y color (reglas críticas)
// Estado SLA (delta = disponibilidad - objetivo)
if delta >= 0       → "CUMPLIDO"   (verde)
if delta >= -0.5    → "EN RIESGO"  (amarillo pulsante)
if delta <  -0.5    → "INCUMPLIDO" (rojo animado)

// Color interpolado continuo verde→amarillo→rojo
delta >= 0           → #00e676 (verde puro)
-0.3 <= delta < 0   → iC(verde, amarillo, t)
-1.5 <= delta < -0.3 → iC(amarillo, rojo, t)
delta < -1.5         → #ff1744 (rojo puro)

Riesgo de disponibilidad
CDN externos sin SRI — dependencia de conectividad
React y Babel se cargan desde cdnjs sin Subresource Integrity. Si cdnjs tiene outage al momento de carga, la app no funciona. Para operación offline/industrial considerar copiar librerías localmente en Docker.
08Decisiones Arquitectónicas
ADR-001
Standalone HTML — cero build step
Contexto
El equipo NOC necesita abrir el dashboard sin instalar nada. No hay DevOps ni CI/CD.
Decisión
Un único .html con Babel transpilando JSX en tiempo de carga. Sin npm, sin bundler.
Evidencia
<script type="text/babel" data-presets="react">
Consecuencias
✅ Despliegue trivial. ❌ ~2-3s overhead transpilación. ❌ Sin tree-shaking. ❌ Difícil modularizar.
ADR-002
Persistencia dual: API REST + localStorage fallback
Contexto
Cada PC tiene su BD local. Para compartir datos se necesita servidor, pero la app debe funcionar sin él.
Decisión
Detección automática por window.location.protocol. File:// → solo localStorage. Http:// → API primero.
Evidencia
const IS_SERVER = window.location.protocol !== 'file:' — App, línea ~549
Consecuencias
✅ Zero breaking change al migrar. ✅ Resiliente a caídas. ❌ localStorage puede divergir del servidor.
ADR-003
JSON flat file como base de datos
Contexto
~60 servicios con 5 semanas/mes. El equipo no administra bases de datos.
Decisión
Un único sla_bd.json leído/escrito con fs.readFileSync/writeFileSync. Sin ORM ni SQL.
Consecuencias
✅ Sin dependencias BD. ✅ Backup trivial. ✅ Docker volume da persistencia. ❌ Sin transacciones. ❌ Last-write-wins.
ADR-004
Lazy loading de Chart.js y XLSX
Contexto
Chart.js (~250KB) y XLSX (~1MB) son pesados. La mayoría de sesiones no los necesitan.
Decisión
Se inyectan dinámicamente la primera vez que se necesitan. Se cachean en variables _chartJs/_xlsx.
Consecuencias
✅ Carga inicial ligera. ❌ Delay en primera apertura de gráficas. ❌ Error si CDN no responde.
ADR-005
Polling 15s para multi-window sync
Contexto
Múltiples técnicos NOC pueden editar simultáneamente. Se necesita sincronización simple.
Decisión
Poll a /api/data cada 15s comparando savedAt. Sin WebSockets ni SSE.
Consecuencias
✅ Sin dependencias adicionales. ❌ Latencia hasta 15s. ❌ Last-write-wins si 2 usuarios guardan en <15s.
ADR-006
PRELOAD hardcoded de 58 servicios
Contexto
En instalación nueva no hay datos. Se quiere funcionar inmediatamente con datos reales.
Decisión
Constante PRELOAD con 58 servicios de Abril 2026 embebida en el JS. Se usa como base al inicializar.
Consecuencias
✅ Zero-config — demo instantáneo. ❌ Actualizar servicios base requiere editar HTML. ❌ ~50KB extra en el archivo.
09Observaciones y Hallazgos
Alto
Sin autenticación ni autorización
Cualquier persona con acceso a la URL puede leer y sobrescribir todos los datos SLA. POST /api/data y GET /api/export completamente abiertos.
→ Agregar HTTP Basic Auth en Traefik o middleware Express. Alternativamente JWT simple para el equipo NOC.
Alto
Race condition en escritura concurrente
Si dos usuarios guardan en menos de 15 segundos, el último sobrescribe sin merge. No hay optimistic locking ni detección de conflictos.
→ Agregar version counter en el payload. El servidor rechaza POST si tiene un savedAt más reciente que el enviado por el cliente.
Medio
Directorio public/ ausente en desarrollo local
server.js sirve ../public/index.html — path que solo existe en Docker (el Dockerfile copia el HTML ahí). Al correr node api/server.js directamente, el frontend no se sirve.
→ Agregar script npm run dev que copie el HTML a public/index.html antes de iniciar.
Medio
Babel CDN en producción — overhead de transpilación
Babel Standalone (~900KB) se descarga y ejecuta en cada carga para transformar JSX. Sin Service Worker ni caché offline.
→ Para v2, pre-transpilar con Babel CLI offline y eliminar dependencia de runtime. Considerar Vite como build tool para evolución futura.
Medio
Export XLS usa XML Spreadsheet, no XLSX real
doExportXLS() genera XML con MIME application/vnd.ms-excel. Excel moderno muestra aviso de compatibilidad.
→ Usar XLSX.js (ya cargado lazy) con XLSX.utils.json_to_sheet() para generar .xlsx reales.
Medio
Sin CORS configurado
No hay headers CORS en server.js. Si se consume la API desde otro origen fallará.
→ Agregar middleware cors con whitelist de orígenes permitidos.
Bajo
allData crece indefinidamente mes a mes
Cada mes agrega un key. Sin archivado, en ~2 años el JSON puede superar varios MB degradando localStorage.
→ Implementar archivado automático de meses con más de 12 meses de antigüedad.
Bajo
Sin rate limiting en la API
No hay limitación de requests. POST /api/data acepta hasta 10MB sin restricciones.
→ Agregar express-rate-limit con límite razonable para la red interna (ej. 60 req/min).
Bajo
CDN sin Subresource Integrity (SRI)
Los 4 scripts CDN no tienen atributo integrity. Riesgo supply-chain teórico.
→ Agregar integrity="sha384-..." a cada script CDN. Cloudflare provee los hashes en su interfaz.
