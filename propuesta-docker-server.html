01 — Situación actual
¿Por qué migrar?
El dashboard actual funciona perfectamente como archivo local, pero tiene limitaciones críticas para trabajo en equipo.

✕ Estado Actual — HTML Local

✕

Datos aislados por máquina. Cada computadora del NOC tiene su propia base de datos. Si alguien ingresa datos en su PC, los demás no los ven.

✕

Sin acceso remoto. Para ver el dashboard hay que estar físicamente en la PC donde está el archivo.

✕

Distribución manual. Actualizar el dashboard significa enviar el archivo por correo/USB a cada equipo.

✕

Sin respaldo automático. Si falla la PC, se pierden todos los datos históricos del SLA.

✕

Requiere internet para CDN. Sin conexión no carga React, Chart.js ni XLSX.

✓ Con Docker Server

✓

Datos unificados. Un solo archivo JSON en el servidor. Todos los usuarios del NOC ven y editan la misma información en tiempo real.

✓

Acceso desde cualquier dispositivo. Laptop, PC del NOC, tablet — con solo abrir el navegador y entrar a la URL.

✓

Actualización centralizada. Un solo git pull + docker compose up actualiza el dashboard para todos.

✓

Datos persistentes en el servidor. Volume Docker garantiza que los datos sobreviven reinicios y actualizaciones.

✓

SSL + dominio propio. https://sla.atisa.com accesible de forma segura desde cualquier lugar.

02 — Propuesta
Servidor Docker Multi-Proyecto
Un servidor único que aloja todos los proyectos de ATISA, cada uno en su propio contenedor, con Traefik como enrutador y SSL automático.
Principio de diseño: Mínimos cambios al código existente. El HTML del dashboard se mantiene prácticamente igual — solo 2 funciones se adaptan para usar la API en lugar de localStorage. Todo lo demás (React, Chart.js, estilos, lógica de negocio) permanece intacto.

05 — Pasos
Plan de Implementación
Proceso en 4 fases. Tiempo estimado total: 2-4 horas en un servidor ya disponible.

Preparar el servidor

Instalar Docker y Docker Compose en el servidor (Linux recomendado). Apuntar el dominio al IP del servidor.

# Ubuntu/Debian
curl -fsSL https://get.docker.com | sh
docker --version  # verificar

# Crear red compartida (una sola vez)
docker network create atisa-network
Tiempo: ~20 min Requisito: acceso SSH al servidor

Levantar infraestructura base

Clonar el repo atisa-server-infra, configurar el dominio y levantar Traefik + Portainer.

# En el servidor
git clone https://github.com/LDominguezIA/atisa-server-infra.git
cd atisa-server-infra

cp .env.example .env
nano .env  # DOMAIN=atisa.tudominio.com

touch traefik/acme.json && chmod 600 traefik/acme.json

docker compose up -d
docker compose ps  # verificar que todo corra
Tiempo: ~15 min Resultado: Traefik activo + SSL listo

Desplegar el SLA Dashboard

Clonar el repo del dashboard, configurar el dominio y construir el contenedor.

# En el servidor
git clone https://github.com/LDominguezIA/Dashboard-Infraestructura-Atisa.git
cd Dashboard-Infraestructura-Atisa

cp .env.example .env
nano .env  # DOMAIN=atisa.tudominio.com

docker compose up -d --build

# Verificar
docker compose ps
docker compose logs -f sla-dashboard
Tiempo: ~10 min Resultado: https://sla.atisa.com disponible

Migrar datos existentes

Exportar la base de datos del navegador actual e importarla al servidor usando la función ↑BD del dashboard.

# En el browser actual (antes de migrar)
# 1. Abrir SLA_Monitor_ATISA_standalone.html localmente
# 2. Click en botón ↓BD → descarga SLA_BD_2026-05-XX.json

# En el nuevo servidor
# 1. Abrir https://sla.atisa.com
# 2. Click en ↑BD → seleccionar el JSON descargado
# 3. Elegir "Reemplazar" → confirmar
# ✓ Todos los datos históricos migrados
Tiempo: ~5 min Resultado: historial SLA completo en el servidor
06 — Escalabilidad
Agregar Proyectos Nuevos
Cada proyecto solo necesita un docker-compose.yml con las etiquetas de Traefik. El reverse proxy lo detecta automáticamente.
Patrón para proyectos nuevos: Cualquier proyecto con un docker-compose.yml que use la red atisa-network y tenga los labels de Traefik quedará disponible en su subdominio automáticamente — sin tocar la infraestructura. 
# Patrón docker-compose.yml para cualquier proyecto nuevo
services:
  mi-proyecto:
    image: mi-imagen
    networks:
      - atisa-network
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.mi-proyecto.rule=Host(`subdominio.${DOMAIN}`)"
      - "traefik.http.routers.mi-proyecto.tls=true"
      - "traefik.http.routers.mi-proyecto.tls.certresolver=letsencrypt"

networks:
  atisa-network:
    external: true  # usa la red compartida

07 — Infraestructura física
Opciones de Servidor
Tres caminos según el presupuesto y requisitos de disponibilidad de ATISA.

VPS Cloud Recomendado

~$6 USD/mes
  • Acceso desde internet
  • IP fija + dominio fácil
  • SSL Let's Encrypt funciona
  • Alta disponibilidad 99.9%
  • Backup snapshots incluidos
  • Contabo / DigitalOcean / Hetzner
  • 2 vCPU · 4 GB RAM · 40 GB SSD

Servidor Local ATISA

$0/mes
  • Sin costo mensual
  • Datos 100% internos
  • Sin dependencia de proveedor
  • Solo accesible en la red local
  • Requiere IP fija o VPN para remoto
  • SSL Let's Encrypt más complejo
  • PC/mini-PC con Ubuntu + Docker

Raspberry Pi / Mini PC

$0/mes
  • Costo único de hardware
  • Consumo mínimo (~5W)
  • Silencioso y compacto
  • Solo red local
  • Sin redundancia
  • Raspberry Pi 4 (4GB) · $55 USD único
  • Ideal para entorno NOC local
Recomendación para ATISA: Si el equipo NOC necesita acceso desde fuera de la red de la empresa (casa, clientes), usar un VPS. Si solo necesitan acceso interno, un mini PC o servidor local es suficiente y más económico. El código Docker funciona igual en ambos casos.
